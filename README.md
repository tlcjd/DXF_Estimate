# DXF 견적프로그램 로컬 웹시험판 V0.5 — 층별 디스크 캐시

## 이번 버전 핵심

- **V0.4.1과 동일한 Python DXF 해석 엔진을 재사용**합니다. 기존 데스크톱 PySide 창이나 CAD COM을 실행하지 않습니다.
- 평면도 도곽(기존 `--■ DXF_공통_도면구분` 레이어의 제목/범위)을 인식하면 그 **층의 도곽 안에 있는 선분/문자/채움만** 분리합니다.
- 각 층을 `web_trial/data/dxf_cache/<서명>/floor_XXX/`에 독립적으로 저장합니다.
  - `lines.bin`: WebGL2/Canvas 호환 20바이트/선분
  - `attrs.bin`: 클릭 정보용 객체 핸들/블록/객체 유형
  - `texts.json`, `fills.json`, `info.json`: 텍스트, 채움, 층 메타 및 빠른 클릭용 공간 범위
  - 최상위 `index.json`: DXF 서명, 층 목록, 선분 수
- 여러 층이 같은 도곽 범위를 공유하면 실제 벡터 파일은 **한 번만 저장**합니다.
- **브라우저에는 사용자가 선택한 층의 데이터만 전송**합니다. 나머지 층은 디스크에 남습니다.
- **재실행 캐시 재사용:** 프로그램 종료 후 재실행하면 마지막 층별 캐시를 복원합니다. 동일 DXF 재선택 시 파일 내용 해시(브라우저 업로드) 또는 로컬 경로+크기+수정시각(경로 열기)을 비교해 재분석을 생략합니다.
- 도곽을 판정하지 못할 경우 층을 임의로 추정하지 않고, 대형 DXF를 **공간별 `영역 NN-NN`**으로 분리합니다. 작은 DXF는 `전체`로 표시합니다.
- 선택 객체 조회는 2,048선분 단위 공간범위 인덱스를 이용해 후보를 좁힙니다. 기존 선분별 원본 핸들/블록 식별도 최대한 유지합니다.
- 층 정렬은 **B3F, B2F, B1F, 1F, 2F, RF, PH** 순서를 따릅니다.
- V0.4.1의 WebGL2/Canvas2D 렌더러, 검정/흰색 배경, 레이어, 선택·줌·팬은 그대로 유지했습니다.
- 인위적인 DXF 업로드 용량 제한·선분 개수 제한을 두지 않습니다. 그러나 PC 메모리와 GPU 자원의 물리적 한계는 있습니다.

## 실행 방법

1. 기존 견적프로그램에는 덮어쓰지 마세요. **웹시험판 V0.4.1 폴더에만 덮어쓰거나 별도 폴더**에서 실행하세요.
2. `웹_시험판_실행.bat` 실행. Python 3.10 이상, `ezdxf`가 필요합니다.
3. `DXF 파일 선택` → `DXF 읽기`를 누르거나, **수백 MB 대형 DXF는 두 번째 줄에 전체 경로를 붙여넣고 `경로 열기`**를 누르세요.
4. 최초 1회는 DXF 전체 해석/캐시 생성이 필요합니다. 작업 진행 중에는 상태 문구가 갱신됩니다.
5. `층` 드롭다운에서 실제 층을 선택합니다. **선택층 데이터만 화면에 나타나야 정상**입니다.
6. 종료 후 재실행하면 가장 최근에 열었던 DXF의 캐시를 자동 복원하며, 같은 DXF는 재분석하지 않습니다.

## 확인할 테스트

- 이전에 287만 선분이 보였던 DXF로 읽어 `층` 드롭다운이 실제 B1F/1F/...인지, 아니면 `영역`인지 확인하세요.
- 한 층의 `선` 숫자가 287만 전체보다 유의미하게 작아졌는지 확인하세요.
- 다른 층 전환 시 그 층 도면만 보이는지 확인하세요.
- BAT를 종료하고 다시 실행하여 캐시가 바로 표시되는지 확인하세요.
- 같은 DXF로 `DXF 읽기` 한 번 더 실행했을 때 **`기존 디스크 캐시 재사용 (재분석 없음)`**이 표시되는지 확인하세요.

## 유의사항

- 최초 DXF 분석 자체는 여전히 기존 Python 파서가 전체 벡터 목록을 메모리에 생성합니다. **수백만 선분 읽기 중 메모리 피크 문제는 이 버전에서 완전히 해결한 것이 아닙니다.** 이번 버전은 분석 이후 층별 저장과 화면 로딩 최적화입니다.
- 직접 불러온 DXF에 도곽용 레이어/층문자가 없으면 층은 자동으로 추정하지 않고 `영역`으로 분할합니다. 실제 층 자동 분리에는 기존 도곽 규칙에 맞는 자료가 필요합니다.
- XREF/블록 정의가 DXF 내부에 비어 있으면 자동 복원이 불가능합니다. CAD에서 외부참조를 바인딩하거나 내용이 포함된 DXF로 내보내야 합니다.
- 웹시험판의 새 디스크 캐시는 **pickle을 사용하지 않습니다.** 기존 Qt 프로그램의 `.pkl` 캐시 읽기 기능은 이전처럼 로컬 신뢰 파일에만 허용됩니다.
- 원본 DXF는 읽기 전용입니다. 서버가 추가하는 파일은 웹시험판의 `web_trial/data/dxf_cache` 디렉터리뿐입니다. 이 폴더를 지우면 DXF를 처음부터 다시 분석해야 합니다.
- 웹 뷰어는 계속 읽기 전용이며, 실/창호/마감 편집과 CAD COM 실시간 연동은 미구현입니다.

## 테스트 명령

```
python web_trial/test_dxf_import.py
python web_trial/test_large_cache.py
```

검증: 실제 DXF 3개 층(B2F/1F/2F) 도곽 판정, 저장/복원, 캐시 적중, REST API에서 층별 선·문자·클릭 조회, 도곽 없는 도면 fallback, 240,000개 가상 선분을 4개 공간 영역으로 저장/재조회. Windows/Chrome에서 실제 287만 선분 DXF의 체감 속도는 별도 확인이 필요합니다.
