0. 새 작업자가 반드시 먼저 알아야 할 핵심
======================================================================

1) 이 프로그램은 인터넷에 공개하는 웹서비스가 아니다.
   Windows PC에서 Python 로컬 서버(127.0.0.1)를 실행하고,
   Chrome 또는 Edge를 --app 모드의 독립창으로 띄우는 완전 오프라인 로컬 앱이다.
   일반 인터넷 브라우저의 기존 탭/프로필과 분리한다.

2) 현재 웹판은 'DXF 직접 읽기 + 층별 디스크 캐시 + WebGL 뷰어 + 도곽 자동인식'까지 구현됐다.
   과거 전체 견적프로그램을 웹으로 모두 이식한 것은 아니다.
   실/벽체/창호 편집, 견적 산출, CAD COM 실시간 연동은 아직 웹판에 없다.

3) 기존 Python 기반 DXF 엔진 중 필요한 코드를 가져와 사용한다.
   특히 app/rooms/core.py의 read_cad_background(), read_drawing_divisions() 및
   app/rooms/background_source_cache.py의 도곽/클리핑 보조 로직을 재사용한다.
   구형 PySide6 메인 창을 실행할 필요는 없으며, 웹판에는 실질적으로 필요한 파일만 남겼다.
   단, 구형 데스크톱 앱과 웹판의 복잡한 동적블록/XREF 처리 동등성은 검증 대상이다.

4) 원본 DXF/DWG, 기존 프로젝트 폴더를 절대 수정하지 않는다.
   웹판이 생성하는 캐시와 사용자 선택 정보만 웹판의 전용 데이터 폴더에 저장한다.

5) 기능 추가 시 V0.5.6의 빠른 도면 렌더링, 흰색/검정 배경,
   층별 캐시·재사용, 강제 재분석, 진단 로그 기능을 훼손하지 않는다.
   파일 하나 수정해도 관련 자동 테스트를 수행한 뒤 전달한다.

6) 선분 개수·DXF 파일 크기에 임의의 하드 제한(예: 200만 선분)을 다시 걸지 않는다.
   매우 큰 파일은 스트리밍/분할 처리와 실제 메모리 상태 경고·취소를 우선 검토한다.

1. 개발 목적 및 사용 환경
======================================================================

- 목표: DXF/CAD 도면을 분석하여 층·실·벽·창호를 인식하고, 향후 건축 견적/수량산출 기능으로 확장.
- 현재 단기 목표: 웹판에서 DXF를 정확히 읽고, 층별로 분리·캐시 저장하며, 화면에 빠르고 선명하게 표시.
- 화면: Chrome/Edge 독립 앱 창. 별도 인터넷 접속 불필요. UI는 HTML/CSS/JavaScript.
- 엔진: Python + ezdxf. 웹 백엔드는 현재 Python 표준 라이브러리 http.server 사용.
- 렌더링: WebGL2(GPU, 기본) + Canvas2D(CPU, 대체). 문자/채움은 별도 Canvas.
- OS: Windows 11 사용자 환경. 개발자가 Linux에서 테스트할 수 있지만 Windows 실행 검증이 최종 기준.
- 배포: ZIP 압축 해제 후 웹_시험판_실행.bat 실행.
- 파일명: 한글 표시명은 가능하지만 다운로드 인코딩 문제가 있어 배포 ZIP 실파일명은 영문 우선.
- UI/진단/로그에서 특정 CAD 제품명 대신 일반 용어 'CAD' 사용 선호.

3. 실행 및 개발 환경 구성
======================================================================

[Windows 사용]
1. V0.5.6 소스 ZIP을 독립 폴더에 압축 해제한다.
2. Python이 있어야 한다. 필요한 기본 DXF 의존성: ezdxf.
   예: py -3 -m pip install ezdxf
3. 웹_시험판_실행.bat 실행.
4. 로컬 서버가 127.0.0.1의 임의 포트에서 실행된다.
5. Chrome 우선, 없으면 Edge를 --app 모드 독립창으로 실행한다.
6. 브라우저를 닫아도 서버가 살아 있을 수 있다. CMD에서 Ctrl+C로 완전 종료.

[직접 실행 / 테스트]
  python -m pip install ezdxf
  python -m web_trial.server --no-browser --port 8765
  브라우저에서 http://127.0.0.1:8765/ 접속

[주의]
- BAT는 같은 폴더나 주변의 기존 프로그램 .venv를 우선 찾고, 없으면 Python Launcher/System Python을 쓴다.
- 자동으로 찾아진 .venv에 ezdxf가 없으면 설치가 필요하다.
- 브라우저 프로필: Windows LOCALAPPDATA/DXF_Estimate_Web/ChromeAppProfile.
- server.py에는 이전 사용자 환경의 경로를 시도하는 기본 폴더 선택 코드가 남아 있다.
  장기적으로 하드코딩 경로를 설정 UI로 대체할 것.
- OS에 따라 인코딩 문제를 피하려면 BAT는 Windows CRLF를 유지하고,
  TXT 로그는 UTF-8 BOM으로 저장하는 편이 안전하다.

4. 현재 구현 기능 — 버전 이력

[PoC V0.1~V0.3]
- 구형 견적프로그램이 만들어 놓은 2단 원본 벡터 .pkl 캐시를 읽어 웹에 표시.

5. 현재 DXF 데이터 처리 파이프라인
======================================================================

[DXF 파일 업로드 또는 PC 경로 직접 열기]
  → web_trial/server.py : DXFJobs.begin() / import_dxf()
  → ezdxf.readfile(path)
  → app.rooms.core.read_drawing_divisions(modelspace)
  → web_trial.auto_frames.discover_plan_frames(...)
       = 기존 도곽 + 자동 후보 + 사용자 선호 후보 + 판정보류
  → app.rooms.background_source_cache.floor_frame_rects()
  → app.rooms.core.read_cad_background(doc, crop_rects=...)
       = 블록/XCLIP/숨김/선·문자·채움 등 해석
  → web_trial.disk_cache.write_cache()
       = 선분 도곽 클립, 층별 바이너리·JSON 저장
  → 저장된 층 목록을 Web UI로 제공
  → 선택층만 web_trial.disk_cache.floor_scene()으로 읽기
  → WebGL2/Canvas2D 렌더링

[중요한 현 구조의 한계]
- 최초 DXF 분석에서는 read_cad_background()가 전체 벡터를 Python 리스트에 보관.
  수백만 선분에서 메모리 피크가 높음. 층별 디스크 캐시는 분석 완료 후의 개선이다.
- read_cad_background의 전체 메모리 처리와 write_cache의 층별 분할은 별도 단계.
  '선택층만 로딩'을 '최초 파싱도 스트리밍'으로 오해하지 말 것.
- 직접 DXF 읽기는 CAD COM 라이브 연결이 아니다.
  내용이 비어 있는 외부참조 블록의 복원은 별도 과제이다.
- 현재는 read-only 도면 뷰어이다. 좌표/도형을 사용자가 바꾸는 편집은 아직 미구현.

6. 캐시/로그 구조와 정확한 포맷
======================================================================

[생성 캐시 경로]
  web_trial/data/dxf_cache/<64자리 시그니처>/
      index.json
      COMPLETED
      floor_000/
          lines.bin
          attrs.bin
          info.json
          texts.json
          fills.json
      floor_001/ ...

[기타 사용자 선택/운영 파일]
  web_trial/data/dxf_cache/frame_choices/<시그니처>.json
  web_trial/data/dxf_cache/last_opened.txt
  web_trial/data/last_dxf_read.txt
  web_trial/root_path.txt

[정확한 필드/파일 규칙]
- disk_cache.py : CACHE_VERSION = 7
- 선분: LINE_STRUCT = struct.Struct('<4f4B'), 20바이트/선
  x1,y1,x2,y2는 float32 / rgba 자리는 RGB 3바이트 + 표시 플래그 1바이트.
  도곽(층) 원점을 빼서 좌표를 상대값으로 저장.
- 객체정보: ATTR_STRUCT = struct.Struct('<QHH'), 12바이트/선
  원본 handle 정수형, 블록 이름 테이블 인덱스, 엔티티 종류 테이블 인덱스.
- CHUNK_LINES=2048: 2048개 단위 Bounding Box로 클릭 후보 구간 감소.
- info.json: rect/origin/layers/totalLines/totalTexts/totalFills 등.
- index.json: signature/cacheVersion/floors/sourcePath/stats 등.
- COMPLETED 파일이 있고 index와 각 층 데이터가 맞아야 완료 캐시로 인정.
- 같은 도곽이 여러 층을 대표하는 경우 floor index에서 같은 디렉터리를 가리킬 수 있음.
- 원본 DXF 경로에서 열 때: 경로 + 파일 크기 + 수정시각(ns) + 캐시 버전으로 서명.
  파일 업로드 시: 업로드 내용 해시와 캐시 버전으로 서명.
  (경로 기반 서명은 전체 DXF 내용 해시는 아님.)
- 강제 재분석 시 새 캐시를 *.building.*에 만든 뒤 성공하면 교체;
  실패 시 이전 캐시를 지키도록 설계.
- 구형 .pkl 지원은 이전 프로젝트 캐시 '조회'용; 새 DXF 캐시는 pickle이 아니라 바이너리+JSON.
- 사용자에게 보여 주는 TXT는 UTF-8 BOM 사용.

[Git 관리]
- 생성 캐시·로그·브라우저 프로필은 커밋하지 말 것.
- 실제 현장 DXF/DWG도 원칙적으로 Git에 올리지 말 것(용량/기밀/저작권).

7. 주요 API / 서버 구현 위치
======================================================================

로컬 서버: web_trial/server.py, http.server.ThreadingHTTPServer
바인드: 127.0.0.1, 임의 포트 또는 --port로 지정

GET  /                             웹 UI
GET  /app.js                       프런트 JS
GET  /style.css                    프런트 스타일
GET  /api/config                   설정/현재 도면
GET  /api/catalog?root=...         기존 2단 .pkl 프로젝트 캐시 검색
GET  /api/recommended             유효 기존 캐시 추천
GET  /api/floors?id=direct         현재 DXF 층 목록
GET  /api/scene?id=direct&floor=... 해당 층 장면 메타데이터
GET  /api/geometry?id=direct&floor=... 선분 바이너리
GET  /api/texts?id=direct&floor=... 문자 JSON
GET  /api/fills?id=direct&floor=... 채움 JSON
GET  /api/pick?...                클릭 선분 정보
GET  /api/dxf/job?id=...          DXF 읽기 상태/시간
GET  /api/dxf/frames              도곽 인식·대안·보류 보고
GET  /api/dxf/log                 최신 DXF 로그 TXT

POST /api/dxf/upload              DXF 바이너리 업로드
POST /api/dxf/open-path           PC 로컬 DXF 경로 직접 열기
POST /api/dxf/cache/delete        현재 DXF 생성 캐시만 삭제
POST /api/dxf/frame/choose        대안 도곽을 선택하고 다시 분석
POST /api/dxf/frame/reset         사용자 도곽 선택을 해제하고 재분석

- DXF 작업은 DXFJobs가 백그라운드 스레드에서 실행. 현재 한 번에 한 분석 작업만 허용.
- 강제 재분석: 요청 헤더 X-Force-Rebuild: 1 사용.
- /api/dxf/upload는 임시 DXF 파일을 분석 완료 후 삭제한다.
- /api/dxf/open-path는 입력한 원본 DXF 파일을 읽기만 한다.
- 분석 중 작업취소 UI/API는 아직 없음.

8. 도곽 자동인식의 현재 규칙 및 효제동 검증
======================================================================

구현 위치: web_trial/auto_frames.py — discover_plan_frames()

우선순위:
  1) DXF의 기존 도곽 지정 정보(특정 레이어)
  2) 지정되지 않은 층: 평면도 제목 TEXT/MTEXT + 사각 도곽 후보
  3) 동일 층에 복수 도면: 대표 1개 + 선택 가능한 대안
  4) 실제 사각형이 없고 제목 3개 이상이 규칙적 배치: 가상 도곽(검토 필요)
  5) 제목/경계 모호: 판정보류. 아무 사각형이나 자동 배정하지 않는다.

사각 탐색:
- 닫힌 LWPOLYLINE/POLYLINE 직사각형 후보.
- 수평/수직 LINE 4개로 된 사각형 후보.
- 제목 위치, 도곽 경계 포함관계, 반복 크기, 같은 줄 제목 간격 등으로 평가.
- '창호평면도', 'KEY PLAN', 일반 주석 등을 평면도 제목으로 잘못 채택하지 않도록 필터.
- '4~20F'와 같은 층 범위는 층별 표기로 전개하되 벡터 데이터 중복 저장 방지.

효제동 평면변경안.dxf (실제 사용자 제공 예시 / 현장 도면, Git에 원본 업로드 금지 권장):
- 부분 지정 상태: 기존 지정 도곽 6개(B2F, B1F, 1F, 2F, 3F, 4~20F) 유지.
- V0.5.5 이전: 일반 사각 후보 3,668개 / 평면 제목 후보 71개,
  미지정 자동확정 0개여서 개선 필요했음.
- V0.5.6: 기존 6개 유지 + 지붕 RF / 옥탑지붕 PHR 후보 추가.
- 같은 층 다른 위치 도곽 후보 47건 검출.
- '기존 지정 도곽이 전혀 없는 상황'을 가정한 시험에서는 대표 평면 영역 8개 탐색.
- 위 검증은 도곽 분석 및 API·합성 도면 시험을 포함하며,
  실제 Windows Chrome에서 사용자의 대형 현장 DXF 전체가 정확하게 보이는지는 계속 검증해야 함.

구현상의 주의:
- 가상 도곽, 신뢰도 낮은 후보를 견적 산출의 확정 경계로 사용하지 말 것.
- 수동 도곽 선택값은 자동판정보다 우선해야 하고, 원본 DXF는 변경하지 말 것.
- 자동인식 신뢰도 향상 시 기존 지정 도곽을 덮어쓰지 않는 회귀 테스트 필수.
- 중복 도곽/선택 후보는 버리는 대신 도면 위에서 시각적 비교가 가능하도록 확장 예정.

[알려진 기술적 한계/위험]
1) 최초 DXF 분석 메모리 피크 높음. 수백만 선분을 Python 객체로 모두 전개한다.
   외부 검토자는 240만 선분 합성 DXF에서 약 3.3GB 피크/105초를 관찰했다고 보고했으나,
   이 수치는 사용자 실제 CAD 환경에서 측정한 값이 아니며 재측정 필요.
2) 일부 XREF/동적블록은 DXF에 실형상이 없을 경우 복원 불가.
   과거 Qt 버전에서는 연결 CAD에서 블록 정의 보충/현재 CAD DXF 직접 Export를 시도했으나,
   웹판에는 해당 COM 연동 전체가 없다.
3) 일부 미지정 도곽은 제목/형상이 부족해 자동판정 실패 또는 가상 경계에 오차 발생 가능.
4) 단일 층의 선분이 매우 많으면 화면/메모리 성능을 추가 최적화해야 함.
5) WebGL 선분은 GPU, 문자/채움은 Canvas로 처리되어 CAD 문자 품질과 차이 가능.
6) 현재 클릭 선택은 CHUNK_LINES=2048 공간 청크 Bounding Box로 후보를 줄이지만,
   복잡한 층에서 성능 측정 및 더 세밀한 공간 인덱스 개선 여지 있음.
7) 생성 파일/로그를 정리하는 캐시 관리 기능은 현재 '현재 캐시 삭제' 중심.
   모든 도면 캐시의 용량 조회·정리 UI는 추가 필요.
8) HTTP는 127.0.0.1 로컬만 수신하지만 Host 헤더·DNS rebinding 등 보안 점검 여지 있음.
9) 부하가 큰 작업의 취소·중간 메모리 보호·재시도 UI가 아직 미흡.
10) 브라우저 측 WebGL GPU 프레임 시간과 Python 분석 시간을 구분해 측정할 필요가 있음.
11) 프런트 UI 내 일부 버전 표시 텍스트가 V0.5.5로 남아 있을 수 있음;
    실제 기준은 README 및 CACHE_VERSION=7 / 소스 내용으로 확인.
